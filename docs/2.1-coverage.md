# ModiCom 2.1 coverage gaps (temporary)

This is a working document for adding automated coverage of Status
and Core. It is not permanent documentation: when every item below
is done, fold a short note into the 2.1 section of
`docs/history.md`, update Deferred Test Work in `tests/README.md`,
and delete this file.

Working rules:

- One concern (row) per commit. Re-run all green suites before
  considering that step done. Do not create commits unless the
  maintainer explicitly asks.
- Prefer thin behavioural cases over full-screen golden images.
- Reuse `THARNESS` for edit-buffer setup and the `TEDITIN`
  BIOS keyboard-script pattern for key-driven Core cases. Do not
  invent a third harness style.
- Do not change production behaviour in the same commit as a new
  coverage suite. If a small harness fix is required to compile or
  link, record it in the Status column.
- The probe/green suites remain the truth. If a step breaks a
  green run, fix or revert that step before continuing.
- Update this row’s Status in the same change set as the work.

## Why

Navigate, Buffedit, File I/O, Search/Prompt, Keyboard, Strings, and
Video already have green suites. Status and Core in `TEXTEDIT.C`
(`ctrlkey`, `textedit`, session abort) do not. Closing those gaps
pins the remaining module boundaries without blocking other
deferred work (case-ID renames, `TEDITIN`→`THARNESS`, probes,
error-path IO).

## Coverage queue

| # | Work | Notes | Status |
|---|------|-------|--------|
| 1 | Status suite (narrow) | `TSTATUS` greens for `helptoggle` globals, `showpos` / `scoreboard` / `statmsg` status-line text, and `msg` with scripted Space. Help-screen content and `showstatus` latch left out. | Done |
| 2 | Core `ctrlkey` | `TCTRLKEY` greens for Find / Find-again / cancel / miss / alias / unknown via scripted BIOS keys and `THARNESS` buffer asserts. `ctrlkey` read/write file paths and the `textedit` session loop left out. | Done |
| 3 | Core `textedit` / session abort | Session-level cases only after row 2 is green and boring: load/loop/quit or abort paths that can run unattended. Keep scope small; hang-prone interactive waits stay probes or manual smoke. | Open |

After each row: rebuild via `TESTS.MAK`, run all green suites
(including any new one), confirm production `MODICOM /?` still
shows `v2.1m` if production objects were touched (usually they
are not).

## Out of scope

- Case-ID renames
- Folding `TEDITIN` destination guards into `THARNESS`
- Full help-screen or colour-attribute golden tests unless a later
  row explicitly adds them
- Production behaviour changes
- Fuzzing, crash investigation, nonexistent-file IO paths
