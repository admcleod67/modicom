# ModiCom 2.1 test alignment (temporary)

This is a working document for aligning the green/probe suites with
the post-split editor modules. It is not permanent documentation:
when every item below is done, fold a short note into the 2.1
section of `docs/history.md` and delete this file.

Working rules:

- One concern (row) per commit. Re-run all green suites before
  considering that step done. Do not create commits unless the
  maintainer explicitly asks.
- Prefer docs and include/prototype cleanup before moving cases or
  renaming executables.
- Do not change production behaviour in the same commit as a test
  alignment step. If a small harness fix is required to compile or
  link, record it in the Status column.
- The probe/green suites remain the truth. If an alignment step
  breaks a green run, fix or revert that step before continuing.
- Update this row’s Status in the same change set as the work.

## Why

Production `EDITOR.C` was split into Core, Status, Navigate, Edit,
File I/O, Search, and Prompt (see the 2.1 section of
`docs/history.md`). The green suites still largely describe and
declare against a monolithic editor:

| Suite today | Rough coverage | Still says / uses |
|-------------|----------------|-------------------|
| `TSTRINGS` | Strings | Already aligned |
| `TVIDEO` | Video | Already aligned |
| `TEDITIO` | File load/save | Docs say `EDITOR.C`; local `loadfile` / `textwrite` decls |
| `TEDITOPS` | Navigate + Edit (+ paging) | Docs say `EDITOR.C`; local nav/edit prototypes; ~980 lines |
| `TEDITIN` | Keyboard `getline` + Prompt (+ `findprompt`) | Local `prompt` / `findprompt` decls; docs partly updated |

Link lines already pull the new modules (`STATUS` / `NAVIGATE` /
`EDIT` / `FILEIO` / `SEARCH` / `PROMPT`). Alignment is about
clarity and maintainability, not missing objects.

## Target mapping

| Suite (current or proposed) | Primary production units |
|-----------------------------|--------------------------|
| `TSTRINGS` | `STRINGS` |
| `TVIDEO` | `VIDEO` |
| `TEDITIO` | `FILEIO` (Core globals via `EDITOR.OBJ` as today) |
| Navigate ops (today inside `TEDITOPS`, `N` / `V` groups) | `NAVIGATE` |
| Edit ops (today inside `TEDITOPS`, `E` group + edit probes) | `EDIT` |
| `TEDITIN` | `KEYBOARD` + `PROMPT` (+ `findprompt` in `SEARCH`) |

Core (`textedit` / `ctrlkey` / `abortedit`) stays out of automated
coverage for now unless a later row adds a dedicated harness.

## Alignment queue

One row per commit. Prefer finishing docs/includes before splitting
or renaming suites.

| # | Work | Notes | Status |
|---|------|-------|--------|
| 1 | Docs + module headers | Update `tests/README.md` source paths. In `TEDITIO` / `TEDITOPS` / `TEDITIN`, `#include` the matching module headers (`fileio.h`, `navigate.h`, `edit.h`, `prompt.h`, `search.h` as needed) and drop redundant local prototypes. Prefer `editor.h` externs over duplicate global `extern` lines where already covered. No case moves, no EXE renames. | Open |
| 2 | Split `TEDITOPS` | Carve Navigate (`N` / `V` and related probes) vs Edit (`E` and edit probes such as `X3`) into separate suites (or one intermediate commit that only sections the file if a full split is too large—prefer a real split). Wire both in `TESTS.MAK`; keep green/probe CLI behaviour. Update `tests/README.md`. | Open |
| 3 | Rename / align suite names (optional) | Only after row 2 is green and boring. Align executable or source names with modules if still desirable (e.g. clearer nav/edit names). Skip if current names remain fine. | Open |

After each row: rebuild via `TESTS.MAK`, run `TSTRINGS`, `TEDITIO`,
`TEDITOPS` (and any new suite from row 2), `TEDITIN`, `TVIDEO`,
confirm production `MODICOM /?` still shows `v2.1m` if production
objects were touched (usually they are not).

## Out of scope

- New green coverage for Core (`textedit` / `ctrlkey`) unless added
  as its own later phase
- Behaviour changes to production modules
- Collapsing Status into a dedicated suite (no Status-only harness
  today; leave unless a clear need appears)
